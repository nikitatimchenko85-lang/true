# TRUE DETAILING — планировщик записи

Запись клиентов для администраторов TRUE: шиномонтаж, мойка, СТО, детейлинг (антикор — выключен, включается в настройках).
Сделано по брифу «Единый планировщик записи TRUE» (17.10.2026).

## Что умеет

- **Сетка дня по постам** выбранного подразделения или всех сразу. Шиномонтаж: 4 поста (2 Автолюкс по 60 мин,
  2 Валькор по 120 мин), шаг 30 минут, 8:00–23:00.
- **Тапнул в свободное окно — записал.** Обязательна только машина; пост и время берутся из места касания.
  Клиент, телефон, вид работы, класс и радиус — по желанию.
- **Быстрые пометки одним касанием:** договор, хранение, Run Flat, далее мойка, машина уже в центре.
- **Пересечения ловятся сразу**, в момент записи. Плюс защита в самой базе от одновременного сохранения.
- **Mercedes на Валькоре** — предупреждение при записи (ограничение настраивается у каждого поста).
- **Перетаскивание** записи на другое время или пост: мышью или удержанием пальца на телефоне.
- **Статусы:** записан / не приехал / отменил заранее (для СТО и детейлинга ещё «в работе», «ждёт запчасти», «готово»).
  Записи не удаляются — отмена освобождает пост, но остаётся в истории.
- **«Записать дальше»** — из записи шиномонтажа сразу создать запись этой машины на мойку и т.п.
- **Калькулятор** шиномонтажа по прайсу — отдельным экраном, с записью не связан.
- **Поиск** по машине, номеру, клиенту, телефону.
- **Каждый листает дни сам** и не сбивает других; изменения коллег приходят сразу.
- **Ярлык на телефоне:** открыть сайт → «Поделиться» → «На экран Домой» (iPhone) или меню → «Добавить на главный экран» (Android).
- **Настройки без программиста:** подразделения, посты, юрлица, длительности, ограничения, виды работ, администраторы.
- **Загрузка старых записей** из листа «Заявки Шиномонтаж» (CSV) — Настройки → внизу.

## Запуск на GitHub Pages (бесплатно)

1. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Влейте PR в `main` (или запустите **Actions → Deploy to GitHub Pages → Run workflow**).
3. Через 1–2 минуты приложение откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

Без базы приложение работает в **демо-режиме**: записи хранятся только в том браузере, где их создали.
Чтобы все сотрудники видели одни и те же записи, подключите Supabase.

## Общая база для всех сотрудников (Supabase, бесплатно)

1. Зарегистрируйтесь на https://supabase.com и создайте проект (регион поближе, например Frankfurt).
2. **SQL Editor → New query**, вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql), нажмите **Run**.
3. **Authentication → Sign In / Providers**: отключите **Allow new users to sign up**, чтобы посторонние не могли зарегистрироваться.
4. **Authentication → Users → Add user → Create new user**: создайте аккаунт каждому сотруднику (email + пароль,
   галочка *Auto Confirm User*).
5. **Project Settings → API**: скопируйте *Project URL* и ключ *anon public*.
6. В GitHub: **Settings → Secrets and variables → Actions → New repository secret**, добавьте два секрета:
   - `VITE_SUPABASE_URL` — Project URL
   - `VITE_SUPABASE_ANON_KEY` — anon public key
7. **Actions → Deploy to GitHub Pages → Run workflow**. После сборки приложение попросит войти.
8. Войдите, откройте **Настройки** → внизу «Загрузить записи из Google Таблицы» и загрузите CSV листа
   «Заявки Шиномонтаж» (Файл → Скачать → CSV). Записи на уже занятое время будут показаны как пропущенные.

Ключ *anon* можно хранить в сайте, он публичный по задумке Supabase: данные закрыты правилами доступа,
читать и менять записи могут только вошедшие сотрудники.

> На бесплатном тарифе Supabase ставит проект на паузу после 7 дней без единого запроса.
> При ежедневной работе это не случится; если всё же уснул, его включают кнопкой *Restore* в панели Supabase.

## Разработка

```bash
npm install
cp .env.example .env.local   # по желанию: ключи Supabase
npm run dev                  # http://localhost:5173
npm test
npm run build
```

Стек: Vite + React, Supabase (Postgres + Auth + Realtime). Логика времени, пересечений и стандартные подразделения —
`src/lib.js`, данные — `src/store.js`, прайс — `src/prices.js`, импорт CSV — `src/importCsv.js` (всё покрыто тестами).
